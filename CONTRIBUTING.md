# Contributing to PV Info

Help improve source-linked pharmacovigilance information, accessible workflows and reproducible data collection. Coverage and intended-use limitations must remain visible.

## Start locally

Read [local development](docs/local-development.md), then run the relevant tests. Use a branch and a pull request; describe the problem, resulting behavior, verification and coverage limits. Keep changes focused. A public repository is not a licence grant: this repository has not yet selected a general source-code licence. Resolve contribution and reuse terms with the maintainer before submitting substantial code. Third-party assets retain their own terms.

## Useful contributions

- Search, accessibility, navigation and clear failure states.
- Public-source connectors with bounded requests, provenance and reproducible fixtures.
- Domain review of source interpretation and realistic synthetic scenarios.
- Setup documentation and tests that exercise meaningful behavior.

Discuss broad features in an issue first. A feature proposal is not a release commitment.

## Evidence and privacy

Use synthetic examples. Never attach real case data, patient information, private portfolios, assessments, credentials or internal planning. Cite official documents and distinguish regulatory decisions, label dates and observed text changes. Matching names does not prove product identity or ownership. A label warning alone does not establish a reporting obligation.

Do not redistribute licensed terminology or source documents without the necessary rights. AI-assisted contributions need human review, source verification and the same tests as other changes. Explain material generated content in the pull request.

## Review and release

Tests must pass or failures must be understood and documented for review. Changes to data interpretation need domain review as well as technical review. Permissions and tenant boundaries must be enforced beyond the UI. Do not include production deployment triggers, execute live database changes or publish releases as part of routine contribution work.

Be respectful and specific in discussion. Critique the work, protect confidential information and avoid harassment or personal attacks. Maintainers may close inappropriate discussions or remove unsafe material.

For suspected vulnerabilities, follow [SECURITY.md](SECURITY.md) rather than public issues.
