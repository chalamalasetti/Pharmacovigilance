# Requirements Library — first release

The public Requirements Library captures clause-level FDA and EU/EMA interpretations, with citations and version history. It is an intentionally incomplete starter set, not a certified legal requirements service. The initial 12 records across six source families are pending expert review. No review is generated by AI or inferred from an official publication.

## Workflow

1. Browse latest captures; filter agency, topic, clinical/marketed lifecycle and text.
2. Open the source, specific edition and clause. Read authority, applicability, exceptions and historical gaps.
3. An app admin appends a new version, classifies the change and supplies a change rationale. The predecessor remains readable. First capture is distinct from a new obligation.
4. An app admin approves or rejects the latest pending interpretation with a public rationale. A finalized review cannot be changed; corrections require another version. App admin access is an editorial permission, not evidence of professional qualification.
5. The approved baseline view selects versions using both effective date and approval/knowledge date. Unknown effective dates, drafts, uncertain sources, expired versions and withdrawals cannot masquerade as a current baseline. Pending successors do not replace approved predecessors. Dates are inclusive start/exclusive end. This is a view of captured interpretations, not a statement that every applicable requirement has been captured.
6. Select a confirmed company portfolio and explicitly choose private workspace or a team. Jurisdiction matching is only a screening signal. Confirm product authorization, sponsor/MAH role, outsourced responsibilities, therapeutic scope and clinical/marketed processes in the assessment.
7. The existing Action Center records applicability, assignment, evidence, verification and closure. A pinned requirement UUID and portfolio revision remain in the case snapshot. A later public library version does not silently change an existing case.

## Data and security

- `pv_requirement_versions`: public organizational summaries and source metadata. Append-only content and predecessor chain; only pending review status may transition once.
- `pv_requirement_audit`: admin-only actor UUID and timestamps. Public responses contain no reviewer identity or company information.
- RPCs `admin_version_requirement` and `admin_review_requirement` require authenticated app admin access. No direct client writes, updates or deletes. Advisory locks and expected predecessor IDs prevent concurrent changes from overwriting work.
- Sources are restricted to FDA, EMA, eCFR and EUR-Lex HTTPS URLs. Field allowlists, lengths, dates, contact/identifier guards and existing narrative validation apply in the database. Arbitrary personal names in prose cannot be perfectly detected; editorial users must enter only organizational summaries. No raw source documents, patient narratives, ICSR uploads or contact harvesting.
- Company scope remains in existing private workspaces/team queues. The library never queries other users' portfolios. Team sharing is an explicit user action using existing membership checks.
- If the live database is unavailable, the page clearly shows the unapproved starter file and disables baseline/upcoming views. It does not reuse a stale approved cache.
- Menu registry and SQL validator include Requirements Library. Existing admin menu layout is preserved and the normalizer adds the new page to Resources. The Admin page links to the editorial desk.

## Boundaries and next increments

This release does not crawl all historical documents, automatically identify regulatory changes, perform AI legal approval, calculate individual case clocks, or certify Argus/Veeva/ARISg configurations. Source titles/edition URLs and summarized clauses are versioned; full original document binaries and their hashes are not archived. No before/after comparison is invented when predecessor text is missing. Public versions and review rationales are visible even when pending/rejected; this editor is not a private drafting tool.

Next: qualified review of the seed; amendment and regional implementation dependencies (including EU ICH overlays); selective predecessor backfill; document checksum observations and human change triage; private company control baselines and evidence mapping; larger server-paginated library/search. The existing hourly collection/refresh and SEO/Search Console jobs are unchanged. Requirement content is live from the database after an admin publishes or reviews it; hourly ingestion does not auto-approve or re-extract requirements.

## Validation

`npm test` covers two-date baseline resolution, pending/withdrawn/future/unknown dates, field comparison, citations, contact/URL validation, private handoff and navigation compatibility. `test/requirements-library.sql` runs synthetic rolled-back tests for admin authorization, direct write denial, concurrency, immutable reviews, predecessor chains and private audit identity. `test/browser/requirements.smoke.cjs` exercises source/detail/history, editorial version/review, private assessment handoff, failure fallback and mobile layout with synthetic fixtures. Browser CI also reruns the existing company briefing, Action Center and Navigation Studio journeys.
