# Action Center: assessment to verified closure

Use the full case workflow, implementation drafts, ownership, evidence and reviewer decisions.

## Open the right case and scope
Open [My Company Action Center](https://www.pvinfo.org/action-center.html). Choose Work visibility: This browser only where offered, My private account, or an authorized selected team. Filter by Company, Market, status and Search cases. Refresh loads the latest available cases.

A pending account cannot use protected company saves merely because a public page can be browsed. A browser-only case is local exploratory work and can be lost with browser data. Use an approved personal/team scope for supported persistent workflows.

Assessment handoffs appear separately from existing cases. Select Start case for a handoff, or select an existing case in Cases. Opening the same handoff should continue its record rather than duplicate it.

## 1 · Review evidence
Read the original source, publication date, why it matched, selected products/markets and pinned portfolio revision. For regulatory cases, open the pinned source comparison/human triage or requirement version. The frozen evidence snapshot records what was used; it does not guarantee the upstream source remains unchanged.

## 2 · Decide applicability
Choose Relevant, Not relevant or More information needed. Enter Decision reason and Save applicability. Include role/product/lifecycle/jurisdiction qualifications and unresolved questions. More information needed leaves assessment work open.

Reassess applicability clears the current action/completion context. Read the warning and preserve any needed work before changing the decision. A closed case must be reopened with a reason; a case awaiting verification must be returned for rework before changing applicability.

## 3 · Assign action
For Relevant items, choose Action type, Owner email, Due date and Action instructions, then Save action. Types include label/product information, signal evaluation, risk management, regulatory submission, safety system/process and literature follow-up.

In team work, choose an authorized team member. Enter only the required work email identifier, without a personal name or patient details. Recording an owner is not a guarantee that an email notification was sent, that the person accepted it or that another enterprise task system was updated.

The dashboard shows Awaiting assessment, Actions due, Overdue, Awaiting verification and Closed. Counts follow the current filters/scope. An overdue date is a workflow indicator, not necessarily a verified statutory reporting clock.

## Draft business, system, process and data requirements
Where the case exposes implementation drafts, create the appropriate business/system/process/data/training requirement against the case's evidence. Specify the current control, proposed change, rationale, acceptance/verification evidence and the applicable system/process scope using the fields offered. Keep drafts separate from the source text and approved baseline interpretation.

Choose Impact requirement type, then complete statement, acceptance criteria, rationale and system scope. Prepare drafting prompts supplies placeholders that you must replace with reviewed company-specific wording. Save draft (or Save new draft revision) creates a new immutable revision. Enter an Impact draft review note, choose the independent team reviewer when required, and Submit draft for review. The designated reviewer can Approve requirement or Return draft for changes; personal work uses explicit self-review. Export private impact requirements downloads this draft/history package separately from the case export. If applicability changed after drafting, append and review a new revision. Resolve pending/rework items before closure approval. For example, a system requirement should name the affected configuration and expected test outcome without inventing the company's current Argus, Veeva Safety or ARISg setup. A generic library prompt does not know your versions, customizations or operating procedures.

## 4 · Submit closure evidence
The assigned team owner can submit completion when the workflow requires it. Enter What changed / work performed, a Supporting evidence label and an HTTPS document link. For Not relevant, record Why no action is required with supporting evidence; a reasoned no-action decision still needs the applicable verification step.

Evidence is currently linked by HTTPS URL. Do not assume the app uploads and archives arbitrary attachments. Use a stable organization-approved location that intended reviewers can access. Do not include access tokens, credentials or personal identifiers in URLs. An evidence link alone does not prove its content was independently reviewed.

For team cases, select an independent reviewer who is a different authorized teammate. Personal/local closure is explicitly marked self-reviewed. Select Submit for verification.

## 5 · Verify or return
The designated team reviewer reviews the submitted work and evidence, enters Reviewer verification note and selects Approve and close. The submitter cannot approve their own team submission through the independent-review route. For a personal case, use Confirm self-review and close and retain the self-review designation.

If evidence is insufficient, enter Rework reason and Return to work. Do not close merely to clear an overdue counter. After closure, Reopen case requires a reason and records another event; it is preferable to pretending a prior decision never existed.

## History, export and save conflicts
Case history records supported transitions, versions, actors and timestamps. Export this private case downloads the case JSON; regulatory-change cases include the supported pinned evidence package. Store it securely and inspect completeness for your intended use. It is not automatically a validated e-signature package or a full database audit export.

If the app reports that another tab/user changed the case, your unsaved form is retained where possible. Copy necessary text, Refresh, compare the current version, and retry deliberately. Do not keep clicking Save to bypass concurrency checks.
