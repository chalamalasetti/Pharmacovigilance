# Requirements Library and baseline releases

Explore source-linked interpretations, distinguish current evidence from approved baselines and assess a pinned version for your company.

## Choose the workspace
Open [Requirements Library](https://www.pvinfo.org/requirements.html). The workspace includes Requirements explorer, Baseline releases, Research intake, Coverage map and Company workflow. Start with the view that matches your task rather than treating every visible row as an approved legal obligation.

## Search and filter interpretations
Use Search, Country/jurisdiction, Agency, Topic and Lifecycle. View distinguishes Latest captures, Awaiting review, Approved baseline on date and Approved upcoming. Applies on is the date the requirement is assessed as effective; Known/approved by restricts what review evidence was available by the selected date.

A latest capture can be unapproved. Approved baseline views exclude undated or unapproved interpretations and apply version/date rules. An unknown start date must not be guessed. The applicable successor is considered before an expired/withdrawn version so an old obligation is not silently resurrected.

## Inspect one requirement
1. Select a requirement and note its stable key and revision.
2. Review Source, Edition/clause, Legal basis, publication/effective interval and review status/rationale.
3. Read Who may be affected, Qualifications & exceptions, Processes to assess, Systems to assess and Historical coverage.
4. Open the captured source document/extraction history and the official link.
5. Use Compare with predecessor to review changed captured fields. A field diff is evidence for interpretation, not the official legal text itself.
6. Inspect earlier versions rather than replacing history with a current summary.

Source register & coverage gaps helps distinguish a registered source from reviewed interpretation coverage. Export shown records exports the current supported view; record the filters and dates when using an export as review evidence.

## Master checklist and agency annexes
Common capability controls provide a cross-jurisdiction checklist. The FDA/US, EMA/EU, MHRA/UK, Health Canada and PMDA/MHLW/Japan annex context distinguishes agency-specific obligations and evidence gaps. A common capability is not automatically a legal obligation in all five jurisdictions. Unverified research candidates, especially sources without verified operative text, must remain clearly separate from approved local obligations.

Use agency/control filters to inspect linked items. Follow exact source citations and distinguish regulation, guidance and technical instruction. Do not infer deadlines, responsible parties or submission routes when the operative source has not been verified.

## Administrator: revise an interpretation or prepare a release
Use the Library editorial desk to capture a new requirement or revise an existing stable key with a new version. Complete the required source, statement, legal basis, applicability, qualifications, dates and rationale fields. Review/approval actions are separate from a save. Existing approved versions are historical evidence and are not edited in place.

Baseline releases has a Baseline editorial desk and Prepare a release. Review the included approved versions, source relationships, release rationale and the resulting release history. Do not describe a merely prepared or unapproved set as an approved organizational baseline. Inspect the actual status and version set after saving.

## Send a version for company assessment
1. Confirm your portfolio in Company Briefing.
2. Select the exact requirement version and Assess for my company.
3. Choose the confirmed Company portfolio and Assessment destination.
4. If intentionally monitoring a source outside selected markets, read and explicitly confirm that choice.
5. Select Send this version for assessment, then continue in Action Center.

The handoff pins that requirement version and company context. An approved library interpretation still needs a company applicability decision. If portfolio data changed, reconfirm it before creating a new assessment. A later baseline revision does not silently replace the evidence in an existing case.
