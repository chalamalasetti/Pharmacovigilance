# Baseline Review: draft to publication

Review automatically prepared requirements against the original document before publishing a human-reviewed version.

## Access the review desk
Sign in with an approved site-administrator account. From Source Documents select the source/capture and Review automatic baseline drafts. You can also open [Baseline Review](https://www.pvinfo.org/baseline-review.html) directly. The current review desk is administrator-controlled; the app does not yet expose every proposed specialist role as a separate permission tier.

Choose Captured document, filter Stage and use Find a clause. The desk prepares supported drafts automatically from the selected capture. Draft count and capture/coverage messages describe available extraction output, not a certification that every regulatory requirement was found.

## Review a draft
1. Select a draft in the list.
2. Read Captured source evidence, its context, citation/anchor and parser/capture status.
3. Open official source and Open archived document. Review the surrounding sections, definitions, tables, exceptions and referenced documents.
4. Check Title, Statement, Authority type, Legal basis, Applicability and Exceptions. A guidance source should not become binding law merely because a sentence uses an imperative word.
5. Expand Source metadata, dates and implementation prompts. Check lifecycle, source status, effective/publication dates, systems/process prompts and change rationale. Locked provenance fields identify the source and must not be casually rewritten.
6. Select Save draft before taking a workflow action.

Record missing information honestly. System prompts are generic assessment aids; they do not establish how Argus Safety, Veeva Safety, ARISg or a company's customized process must change.

## Move through the actual lifecycle
| Stage | Available next actions |
| --- | --- |
| Draft | Save draft; Submit for review; Reject draft. |
| In review | Return to draft; Publish reviewed requirement; Reject draft. |
| Published | Open the published requirement and its history. Use Requirements Library for subsequent revisions. |
| Rejected | Retained decision state; it is not an approved baseline obligation. |

Unsaved edits must be saved before submission/publication. Changing selection while editing can ask whether to discard unsaved changes. If another reviewer changes the record, reload and compare before retrying; do not overwrite a newer revision blindly.

## Publish a reviewed requirement
1. In the in-review draft, enter a clear Decision rationale.
2. Choose a Stable requirement ID for a new obligation. Keep it stable across later revisions of the same underlying meaning.
3. If that stable ID already exists, stop and revise the existing obligation in Requirements Library. The desk intentionally blocks parallel IDs that could duplicate an approved baseline.
4. Confirm Source evidence reviewed only after checking the full source, wording, authority, applicability, conditions, dates and extraction coverage.
5. Select Publish reviewed requirement and inspect the success message.
6. Select Open published requirement and verify its source/version/status in Requirements Library.

Publication is a human-reviewed library decision. Company applicability remains undecided. The current admin workflow does not justify claiming independent dual approval, a validated electronic signature or GxP compliance where those controls have not been implemented and qualified.

## History and omissions
Draft decision history records supported commands, revisions, rationale and times. A previously accepted/rejected candidate is not necessarily redrafted automatically. If no draft appears, inspect the extraction candidate view and the original document; absence can represent prior disposition, unsupported extraction or a coverage gap. Do not repeatedly import duplicates to make the count look complete.

When a source revision arrives, preserve the older source and requirement history, compare evidence and create a reviewed successor interpretation where warranted. Automatic extraction must not overwrite a published baseline merely because new text was detected.
