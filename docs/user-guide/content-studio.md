# Template Library and Document Studio

## Start with a reusable structure

Open **Resources → Template Library & Studio**, or follow the link from the Configuration Workbench. The homepage layout is unchanged. Anyone can browse six reference structures: SOP, work instruction, configuration runbook, validation checklist, training deck and team briefing. Search or filter by audience focus and change type, preview the sections, then choose a template.

These are reusable starting structures, not approved company procedures or a comprehensive library of legal obligations. Audience filters are broad reference categories. Enter the actual organizational roles in the document context. No paid AI drafting service is used.

## Create and populate a private draft

Approved accounts can create personal or team drafts. Choose the scope before creating work; an existing document cannot be moved to another scope. Populate from a saved company assessment to bring across its source, company context, proposed change, implementation text and draft testing material. The assessment ID and revision remain pinned. Draft assessments can seed content, but a linked assessment must be current and approved before document submission or approval.

Alternatively select a captured source document, or enter exact official source metadata. After selecting a capture, choose an exact captured passage to populate the regulatory-basis section with its text and citation. The picker supports up to 200 passages of 6,000 characters each. Selecting a capture does not turn every clause into an SOP. Review the original text and complete each required section. A captured source pins its capture ID and checksum. A newer capture or withdrawn/superseded source blocks submission and approval. Manually entered sources require manual monitoring. The picker is bounded; use the Source Documents library if the required capture is absent.

## Tailor sections and reusable company variants

Enter company scope, markets, safety system and installed version, audience and change type. Sections distinguish source-supported content, company decisions, suggested wording and placeholders. Edit both the section title and content. Complete every NEEDED or TODO placeholder and select the appropriate content basis. Verify exact source edition, location and dates.

The initial templates do not provide verified release-specific Argus clicks, screenshots, configured rollback commands or completed validation results. Add company-reviewed steps and evidence. Do not enter patient information or personal/contact details.

**Save as reusable template** preserves an editable private variant in the selected scope. Variants are versioned reference drafts, not approved company standards. Using one creates a new draft with cleared source/assessment binding and suggested content, so prior-company applicability is never silently reused. The six reference structures are release-controlled. Direct upload of Word templates, branded layout files and screenshot libraries is not part of this release.

## Review and approve

Save the draft with a reason, resolve readiness items and submit for review. Personal documents can be drafted and downloaded, but approval requires a team workspace. A team member who has never authored this document must review each section. Team members can add findings; record a resolution for each finding before approval.

A separate team owner approves the reviewed version. The database blocks self-review, self-approval, unresolved findings, incomplete sections, outdated assessment binding and stale writes. These rules apply even if someone bypasses the browser controls. This release uses the existing team membership and owner roles; it does not introduce configurable multi-stage regulatory/QA approval chains.

Approved content cannot be edited directly. **Create draft revision** preserves prior snapshots, clears current section reviews and approval, and starts a draft. Editing saved content also clears section reviews. History records the content, state, actor account ID, reason, findings and approval for each saved revision. History cannot be changed through ordinary app access.

## Download matching saved versions

Download DOCX and PDF from a saved revision. Training decks additionally support PPTX; their DOCX export is a training outline. PDF uses a bundled Unicode font. Unsupported glyphs produce an explicit error rather than silently disappearing. Long content flows to additional pages or slides. These exports contain the same saved content, with layouts suited to each format.

Unsaved edits block downloads. A draft export carries **DRAFT — COMPANY REVIEW REQUIRED**. Approved exports carry the stored approval account ID and time. Open history to export a specific earlier snapshot. Those exports retain that snapshot's original status; check later revisions before operational use.

Downloads are generated in your browser; no company content goes to an external conversion service. Copies are editable outside PV Info, so their approval is not a cryptographic authenticity guarantee. The application approval is not a validated electronic signature or GxP certification. Document approval does not prove implementation, training completion or validation execution. Confluence publication is not integrated.

## Keep evidence current

The editor warns when its linked assessment changes or its source capture is no longer current. Submission and approval repeat those checks in the database. Previous approved versions remain accessible. Source-library metadata entered manually has no automatic monitoring. Document exports do not automatically close Action Center actions: complete implementation and verification there separately.
