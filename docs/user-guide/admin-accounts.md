# Admin: accounts and access requests

Approve signups, communicate privately and handle assistance without shared passwords or automatic identity bypass.

## Access the module
Sign in with an approved site-administrator account. The Admin menu appears only after administrator authorization is confirmed. Open Admin, then [Accounts & access requests](https://www.pvinfo.org/admin-accounts.html). A regular user cannot gain access by choosing a professional role or knowing the URL.

The screen distinguishes self-signup approvals, password assistance, private legacy access requests and advanced temporary-password provisioning. Use Reload requests when checking a newly created account.

## Approve a self-signup
1. Find the requested user ID in Signup approvals. Confirm you are reviewing the intended registration, especially when similar aliases exist.
2. Follow your organization's approval criteria. Do not infer identity from public profile text alone.
3. Use the organizational message box when an explanation or instruction is needed.
4. Select Approve account or Decline signup. Read the success/failure result and reload to confirm the state.
5. Use Send private message for an account-specific message. Users can read it on Approval status & messages after signing in with their chosen password.

The ordinary self-signup user chooses their own password. Approval does not require an email link, and the app does not guarantee an approval email. Pending users can still navigate public modules; private saved company work remains locked until approval.

## If a signup is missing
Check Signup approvals rather than only Private access requests. Reload, confirm the user's exact user ID and inspect whether account creation actually succeeded. Do not create another privileged user or overwrite an existing account as a shortcut. A setup-incomplete/approving state needs investigation before claiming access is granted.

## Password assistance
Review the Password assistance requests list and select the appropriate available outcome, such as Identity verification needed, User recovered with a code or Duplicate/no action. Record assistance review documents the review; it does not change a password or issue reset authorization automatically.

Never disclose an existing password, ask a user to put their recovery key into public chat/GitHub, or approve account takeover from a user-ID-only request. The recovery-key route is the normal email-independent reset mechanism; missing credentials require a controlled identity process.

## Advanced temporary-password accounts
Use Advanced · manually provision a temporary-password account only when ordinary self-signup is unsuitable. Choose a regular-user ID and optional professional role, link the intended legacy request where applicable, and select Generate account & temporary password.

Copy the unique temporary credentials when shown, share them only through an appropriate private channel with the intended user, and dismiss the secret. The app does not email it automatically or provide a reusable shared default password. It expires, is not retrievable later, and the user must set a permanent password before receiving normal app access. Reissue only for the intended pending account; earlier temporary credentials stop working.

## Account messaging is not public chat
Private approval/status messages are separate from Ask PV Info's public-update search. Current chat should not be advertised as a live support channel or a guaranteed administrator inbox. Keep messages organizational and minimal; do not collect names, birth dates, addresses, phone numbers or patient information.
